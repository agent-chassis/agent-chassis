# Dispatch discovery and runtime boundaries

The production agent tools are `start_agent`, `get_run_result` and
`integrate_work`, as described by the [operation reference](mcp-operation-reference.md).
Retired identity-contract, coordination-preflight, validate-dispatch and shared
agent-dispatch tools are not registered discovery entrypoints. Private backend
operation names describe implementation owners and grant no indirect public route.

## Dispatch identity and bootstrap states

The serving launcher binds one repository, session role and prepared backend.
Caller role claims, environment, prompts and repository selectors grant no
authority. A start selects canonical subject and configured model choices; an
implementation worker requires an exact authored slice. Preview resolves only
its reported capabilities/readiness and produces no allocation or child.

The root WK supplies an explicit base branch and controlled-acceptance disposition.
Required controlled acceptance needs the selected slice's own complete current
obligations. A root whole-work exemption is a separate author choice with an
unassessed rationale. An unchanged bare-WK retry does not select or author a
slice; returned guidance still needs the caller's exact contract inputs.

The [launch and admission](mcp-dispatch-launch-and-admission.md) owner defines
mechanical failures and configured CCE decisions. Coordinator preparation,
design review, implementation review and disposition requirements are repository
conduct policy; these do not create independent local sequencing gates.

## Runtime blocker taxonomy and coordination preflight

Mechanical failures state their cause, selected subject, actual effects and
supported correction. Missing runtime capabilities must not be absorbed by
rewriting the work contract. Correct malformed or stale authoring through
`save_record`; missing branch or scope choices remain author inputs rather than
invented replacement values. A valid schema, preview or authored assessment
establishes neither runtime admission nor successful execution.

Managed workers need a constructed sparse namespace and host MCP conduit.
Claude uses exact writable file mounts and in-place `Bash` edits, while findings
roles have full repository reads and no repository writes. General unenforced
posture does not replace a capability the selected composition actually needs.
The authenticated host test capability is a separate unconfined exception, not
a broader agent shell grant. See [enforcement model](enforcement-model.md).

## Findings, recovery and explicit integration

Observe the same attempt with the exact `get_run_result` call returned by start.
Completion captures a result; original reads and saved dispositions integrate
nothing. Missing durable evidence remains unavailable. Prior process identity
and Git delivery identity are independently authenticated; unresolved attempts
are not permission to relaunch or remove local state. See
[managed-run lifecycle](mcp-dispatch-managed-run-lifecycle.md).

Findings-only review produces advisory text. Schema adherence concerns optional
formal attestation, which grants no general lifecycle authority. Technical
redteam requires its exact independently scoped canonical adversarial unit.
Do not substitute a worker, operator shell or another review when a required
review capability or source is unavailable.

Only explicit `integrate_work({delivery})` reaches the integration owner and
repeats exact delivery/base/ref/source fences and configured policy. Candidate
advancement, publication, landing observation and canonical completion remain
separate operations. See [slice integration](mcp-dispatch-slice-integration.md)
and [terminal review](mcp-dispatch-terminal-review.md).
